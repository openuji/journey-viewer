# Working agreement

Read `PLAN.md` before making changes. It records the agreed architecture, current
checkpoint, stage boundaries, and acceptance gates.

Implement one stage per implementation request. Do not begin later stages or add
placeholder packages. At completion, record verification evidence in `PLAN.md`
and leave changes uncommitted for the user. Only the user may create commits.
Call out proposed changes to agreed responsibilities
or public interfaces before implementing a different architecture.
